# The Lantern and the Hidden Door · A Lux3D-Powered 3D Narrative Space

> English edition of [`demo/README.md`](./README.md). Project of the **Aholo Global 3D AI Hackathon** (Manycore / 群核科技).
> Every 3D prop in this game is generated by **Aholo Lux3D** (image-to-3D), optimized by gltf-transform, and loaded with a procedural-geometry fallback — the playable result of a reusable "3D narrative space pipeline".

A first-person 3D narrative game: on a rainy night you wake in a study that should not exist. Find the light, descend, solve the symbol mechanism — and see what this room has been hiding.

- **Stack**: Vite + React 19 + TypeScript (strict) + three.js + @react-three/fiber + @react-three/drei + Zustand
- **17/17 real Lux3D GLB assets** wired through a three-layer fallback (HEAD probe → Suspense → ErrorBoundary → procedural geometry). The game is fully playable with zero assets.
- **Zero network assets at runtime**: GLBs ship from `public/models/`, sounds are WebAudio-synthesized, Chinese UI is an HTML overlay (no font files, no CDN).

## 3. The 7-step mainline (covered by unit tests)

1. **arrival** — inspect the desk / read the half-written diary → clue `clue_diary`
2. **find_light** — search the bookshelf's third shelf → the brass lantern
3. **light_it** — press `L`; a hidden trapdoor appears by the fireplace
4. **descend** — use the trapdoor → into the basement (impossible without light)
5. **illuminate** — lantern reveals: shower-door outline, stone relief, washbasin inscription
6. **solve_dials** — turn dials **3 → 1 → 2**; wrong order shakes and resets, retry freely
7. **chamber** — through the secret door, inspect the stone altar → ending

Stage progression is strictly monotonic (`applyAction` pure reducer, Zustand store, `localStorage['lux3d.save.v1']` saves with export/import and corrupt-save guards).

## 4. Architecture — why this pairing

```
┌─ Production  pipeline/lux3d — Node ESM + Aholo SDK + gltf-transform
├─ Runtime     demo/ — Vite + React 19 + TS strict + three/R3F + Zustand
├─ Backend     server/ — FastAPI + PostgreSQL/pgvector (mock-first, 13/13 E2E)
└─ Collab      collab/ — file-as-task board for a two-agent (DSH × ZCode) pipeline
```

- **Two-stage generation**: text-to-image (G1-Turbo) reference → image-to-3D (G1, 120k faces, PBR). Image-first gives compositional control; 3D faithfully reproduces it.
- **gltf-transform optimize** (quantize + simplify 0.35 + WebP 1024): raw ≈9.5 MB → ≈1.2 MB per prop (**−89%**) without a Draco CDN decoder, preserving the zero-network rule.
- **GLB-first with a permanent procedural fallback**: every interactive prop sits in a `<PropAsset>` slot — if a GLB is missing or fails to parse, the hand-authored procedural geometry renders instead. The demo can never be broken by an asset.
- **Calibration methodology** (validated on all 17 props): measure each GLB's real bounding box with `gltf-transform inspect`, normalize by *scene-semantic* size (desk top 0.83 m, door 2.2 m…), then apply the wall-orientation convention (GLB faces +Z; west wall +90°, east wall −90°, north wall 0°).
- **Evidence chain**: every pipeline run archives raw GLBs, reference images, task IDs and a report under `pipeline/lux3d/runs/<timestamp>/` — auditable proof that Lux3D produced the assets.
