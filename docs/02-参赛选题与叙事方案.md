## 1. 我们到底在做什么

### 1.1 一句话（30 字内）

> **用 Aholo Lux3D 生成物件，用 Agent 组织故事，做一间能"聊"的书房。**

### 1.2 三句话（给评委的电梯陈述）

1. 3D AI 让"造物"变便宜了，但"**造出来的东西怎么被使用**"还没解决。
2. 我们做了一个垂直切片：一间神秘书房，玩家靠调查物件、提灯照明、解符号机关进入密室——整个书房的可交互物件都由 Aholo Lux3D 生成，并接入我们自研的叙事状态机、知识检索与受控 Agent。
3. 它验证的是一条**可复用生产线**：换成任何空间（展厅、民宿、校史馆、品牌快闪），同一套"资产管线 + 叙事引擎 + 信息导航"可以再生产一遍。

### 1.3 它不是什么（边界，防止误解）

- 不是"AI 一次性生成整座 3D 城市"的炫技 demo；
- 不是纯 3D 模型展示页；
- 不是要复刻 Zork 的完整 30 区域游戏（Zork 是**方法论参考**，不是内容复制对象）；
- 不是只给技术人看的东西——它最终要能让**普通观众**自己走进去。

## 2. 为什么做：三个观察与一个判断

### 2.1 观察一：3D 生成已经很能"造物"，但作品大多止步于"模型"

Aholo Lux3D 的官方能力是**图生 3D / 文生 3D**：输入参考图或提示词，输出带 PBR 材质的 GLB（[官方文档](https://labs.aholo3d.cn/api-docs/skills/lux3d)）。
生成侧越来越强，但大量参赛作品会停在"我生成了一个很酷的模型/场景"。**从"资产"到"体验"之间，缺的是叙事、交互、状态与导航。**

### 2.2 观察二：真正的内容方需要的不是模型，是"空间里发生的事"

博物馆、文旅、品牌、教育客户的真实需求不是"给我 100 个模型"，而是：

- 观众进来后**先看哪里、怎么走、看懂什么**；
- 空间里的内容**能不能被检索、被讲解、被更新**；
- 一套内容**能不能复用**到下一个空间。

这正好对应我们已有的 ECO 信息组织（空间/内容/物件三层）+ ZORK 探索感（逐房间叙事/光照约束/物品谜题/日记提示）的设计底稿。

### 2.3 观察三：本次赛事的评审口径与我们的结构高度一致

官方评审为**专家 70% + 玩家 30%**，五个维度：**群核技术栈应用、作品有趣程度、创新性、完成度、应用价值**（从官网页面提取，最终以官网为准）。
这五个维度恰好对应：资产证据链（技术栈）、提灯+机关（有趣）、检索/Agent 叙事导航（创新）、可运行切片（完成度）、可复用生产线（应用价值）。

### 2.4 我们的判断（机会窗口）

> **"3D 生成 + 叙事引擎 + 信息导航"三件套，是 3D AI 从"作品"走向"产品"的那一步。**
> 群核有 Lux3D / SpatialGen / LuxReal 这套空间智能底座，我们有叙事空间的方法论与工程实现——**两边拼起来正好是一条完整生产线。**

### 2.5 整体思考链路（我们是怎么想到这个方案的）

```
AI 能生成 3D 物体
  → 但生成完就结束，没人"使用"它
  → 使用者需要的是"空间体验"：叙事、交互、状态、信息
  → 所以我们把"生成"接到"叙事空间引擎"上
  → 引擎需要真实资产，正好用 Aholo Lux3D 生产
  → 叙事需要被"讲出来"，正好用 LuxReal 做影像表达
  → 先用一间书房做最小闭环（M0），再复制到更多空间（M1-M3）
```

## 3. 为谁而做

### 3.1 直接用户（买单/使用的人）

| 用户 | 痛点 | 我们给什么 | 成功指标 |
|---|---|---|---|
| **展陈/文旅运营方** | 数字展厅造价高、内容更新慢、观众停留短 | 一套"可探索空间 + 检索导览 + 可换内容"的模板 | 观众平均停留时长、二次传播率 |
| **品牌空间/快闪** | 空间营销同质化，缺少互动记忆点 | 带剧情的品牌空间（线索、解密、结局） | 参与完成率、UGC 分享量 |
| **教育/科普内容团队** | 知识枯燥、缺少空间化表达 | 知识点变成"可调查的物件 + 可问答的 Agent" | 知识点触达率、问答命中率 |
| **独立叙事创作者/小团队** | 3D 内容生产门槛高 | 资料→资产的半自动管线 + 叙事编辑器雏形 | 单位内容制作时长 |

### 3.2 生态视角（群核/评委在意的人）

- 群核的判断是：单点技术领先窗口在缩短，**工具链、场景与开发者生态**才是壁垒（赛事报道原话可参考 [北青网报道](http://finance.ynet.com/2026/10/19/4053026t632.html)）。
- 我们的作品如果成立，就是"**用 Aholo 技术栈做内容生产**"的一个可复制样例：别人拿到我们的模板 + Lux3D，可以生产自己的空间。

### 3.3 体验者（最终观众）

- 不需要懂 3D、不需要装客户端，打开浏览器就能进；
- 有明确目标（找到光、进入地下室、打开暗门），不会"不知道干什么"；
- 有"被故事接住"的瞬间（黑暗中被提灯照亮、镜子里的雾字、密室石台）。

## 4. Lux3D 如何发挥作用

### 4.1 定位：不是"生成几个模型"，而是**内容生产线的核心引擎**

在我们的生产线上，Lux3D 承担"**单件资产**"这一层——但它不是孤立调用，而是被嵌进一条有验收标准的数据流：

```
物件清单（objectId + 语义 + 尺寸）
  → 英文提示词 / 参考图（文生图）
  → Lux3D 图生 3D（G1，PBR，GLB）
  → gltf-transform 压缩（quantize + simplify + WebP）
  → demo/public/models/<objectId>.glb
  → assetRegistry → R3F useGLTF 加载（失败自动回退程序化几何）
```

### 4.2 三层价值（Lux3D → SpatialGen/Viewer → LuxReal）

| 层 | 工具 | 在我们项目里的作用 |
|---|---|---|
| **物体层** | **Aholo Lux3D** | 生成书房/地下室/密室里所有关键可交互物件（书桌、提灯、暗门、浮雕、转盘…） |
| **空间层** | Aholo SpatialGen / Viewer（官方开放能力） | 把单件资产组织成可漫游空间、3DGS 浏览（M2 可选增强） |
| **影像层** | **LuxReal** | 把同一 3D 空间变成跨镜头一致的宣传片/过场（见第 5 节） |

### 4.3 证据链（直接对应评审"群核技术栈应用"）

我们为每件资产保留：

- 提示词（manifest 里可复现）；
- 参考图（`runs/<时间>/refs/`，文生图产物）；
- 3D 任务 ID 与结果 URL（`report.json`）；
- 原始 GLB 与优化后 GLB（`runs/<时间>/raw/` 与 `public/models/`）；
- 压缩前后数据（三角面、体积）。

**已实测数据**（来自本机真实 API 调用）：

| 物件 | 原始 GLB | 优化后 | 三角面 | 用时 |
|---|---|---|---|---|
| 半页日记 `obj_study_diary` | 10.52 MB | **1.18 MB（-89%）** | 118,488 → 41,470 | 生图+3D ≈ 6 分钟 |
| 书桌 `obj_study_desk` | 9.55 MB | **1.12 MB（-88%）** | 约 118k → 41,374 | 生图+3D ≈ 6 分钟 |

### 4.4 边界与诚实说明

- Lux3D 是**单物体**生成，不直接生成整间房；空间组织是我们自己的引擎做的——这正好证明"我们不是只调了个 API"。
- 生成质量依赖提示词与参考图；带文字/复杂符号的物件（浮雕、铭牌）比家具类更难，需要多轮迭代或人工修整。
- 生成物用 Blender 规范化（比例/原点/朝向/碰撞体）是设计中的下一步；本机无 Blender，当前用 R3F 侧包围盒归一化兜底。

## 5. LuxReal 怎么适配、能干什么

### 5.1 LuxReal 是什么（事实）

据群核官方在 WAIC 2026 的发布与人民网报道：**LuxReal 是 AI 视频创作 Agent，已深度接入自研世界模型 SpatialGen**；它可以把平面场景图转为**可交互的 3D 虚拟片场**，为 AI 视频提供"稳定的三维空间底座"，重点解决**多镜头、长视频中的空间一致性**（同一场景换机位不穿帮、道具位置不漂移）。（来源：[人民网报道](http://finance.people.com.cn/n1/2026/0719/c1004-40763564.html)；另见 WAIC 相关报道）

> 注：目前 Aholo 公开 API 文档的 Skills 只列了 **Aholo World** 与 **Lux3D**（[Skill 列表](https://labs.aholo3d.cn/api-docs/skills)），LuxReal 的开放形态/API 能力**以官方为准（待确认）**。比赛期间它作为"开放技术能力"提供，最稳妥的用法是走官方工作台。

### 5.2 在我们项目里的四个落点（按优先级）

| 优先级 | 落点 | 具体做法 | 产出 |
|---|---|---|---|
| **P0** | **90 秒参赛宣传片** | 用我们 Demo 的 3D 场景截图/录屏做参考，在 LuxReal 生成多镜头一致的短片（探索→提灯→机关→暗门） | 必交的"Demo 视频" |
| **P1** | **空间一致性演示** | 同一间书房，3 个机位（书桌/书架/暗门）分别生成再剪辑，证明"换镜头不穿帮" | 报告里的对比图/片段 |
| **P2** | **游戏内过场** | 进入密室时播放 5–8 秒 AI 影像（"上一任屋主的记忆"），作为叙事奖励 | Demo 内一个可播片段 |
| **P3** | **传播短视频** | 小红书/X 用 3 条 15 秒短视频：①提灯点亮瞬间 ②镜子雾字 ③暗门开启 | 加分项（话题词） |

### 5.3 接入路径（按可行性排序）

1. **人工工作台（比赛期最稳）**：把 `demo` 的场景截图/录屏导出，按分镜在 LuxReal 里生成、剪辑；交付 mp4 + 分镜表 + prompt 表。**不需要 API。**
2. **Skill/平台内调用（若开放）**：如果 LuxReal 提供 Skill/MCP/API，用与 Lux3D 相同的方式脚本化（环境变量密钥、任务轮询、下载归档）。
3. **Aholo 平台内嵌（若支持）**：在 Aholo 空间智能平台里直接出片，减少导出导入。

### 5.4 为什么"适配 LuxReal"不是硬蹭

- 我们的叙事空间本来就是"3D 片场"：有固定空间布局、机位（cameraId）与状态。**LuxReal 的空间一致性能力正好服务我们的镜头语言**。
- 反过来，我们也为 LuxReal 提供了"**有剧情的场景素材**"，不是随机生成的视频素材。

### 5.5 分镜表示例（90 秒）

| # | 时间 | 画面 | 声音/字幕 | 对应资产 |
|---|---|---|---|---|
| 1 | 0–8s | 雨夜书房全景，壁炉微光 | 雨声 + 旁白："雨夜，你在一间不该出现的书房醒来。" | 书房 zone |
| 2 | 8–20s | 书桌特写，半页日记 | "找到光，向下走。" | Lux3D 书桌/日记 |
| 3 | 20–35s | 书架暗格滑开，黄铜提灯亮起 | 金属摩擦声 + 心跳 | Lux3D 提灯 |
| 4 | 35–50s | 地板暗门开启，黑暗吞没画面；提灯点亮 | 低频轰鸣 → 安静 | 程序化 + 提灯 |
| 5 | 50–68s | 地下室：淋浴门后暗门轮廓、浮雕三符号 | 水声 + 石刻回声 | Lux3D 淋浴门/浮雕 |
| 6 | 68–80s | 转盘 3-1-2，石门轰开 | 齿轮声 + 石门声 | Lux3D 转盘/暗门 |
| 7 | 80–90s | 密室石台，视线抬起，字幕：Aholo Lux3D × 叙事空间 | 音乐收束 | Lux3D 石台 |

> 若 LuxReal 不可用：用 Demo 真机录屏 + 剪映完成，**视频里必须出现真实运行画面**（赛事要求）。

### 6.3 长版（约 500 字，适合报告书/项目介绍）

> **作品名**：提灯与暗门（The Lantern and the Hidden Door）——一个由 Aholo Lux3D 驱动的 3D 叙事空间
>
> **要解决的问题**：3D AI 让"造物"变得便宜，但多数作品停在"模型展示"。展陈、文旅、品牌空间真正需要的是"观众愿意走进去、看得懂、记得住"的空间体验，以及一套能持续更新的内容生产线。
>
> **我们做了什么**：一个完整可玩的垂直切片。玩家第一人称漫游一间神秘书房，调查书桌、日记、书架、壁炉、镜子，取得提灯；提灯照亮地板暗门，进入地下室；在黑暗中用提灯发现淋浴门后的暗门与浮雕符号，按"3-1-2"转动铜盘，打开暗门进入密室。全程有目标提示、三级提示、日记、存档与结局。
>
> **Aholo Lux3D 怎么用**：书桌、日记、提灯、书架、暗门、浮雕、转盘、石台等关键物件，全部通过 Aholo Lux3D 从提示词/参考图生成 GLB，再经 gltf-transform 压缩（实测 -88%~-89%）接入 Three.js/R3F 场景；每件资产保留提示词、参考图、任务 ID 与迭代对比，形成完整证据链。LuxReal 用于生成跨镜头一致的 90 秒宣传片，展示"同一空间、多个机位"的一致性。
>
> **为什么是我们**：我们不是只调一次 API，而是把 Lux3D 嵌进一条"资产管线 + 叙事状态机 + 知识检索 + 受控 Agent"的生产线：资产可替换、剧情可数据化、检索可导航、Agent 可约束。这使作品既有"能玩"的完成度，也有"能复制"的应用价值——换成展厅、民宿、校史馆，同一套方法可以再生产。

## 9. 90 秒演示脚本（真机录屏版）

> 用于必交 Demo 视频；若 LuxReal 可用，可替换为 AI 影像版或混剪。

- **0–10s 钩子**：黑屏字幕"雨夜，你在一间不该出现的书房醒来"→ 画面亮起，第一人称推门。
- **10–25s 目标**：书桌调查日记，HUD 出现"找到光"；书架暗格滑开，提灯亮起（**第一个高光**）。
- **25–45s 下行**：打开地板暗门，画面转黑；提灯点亮，地下室轮廓浮现（**第二个高光**）。
- **45–70s 解谜**：淋浴门后暗门轮廓 → 浮雕三符号 → 洗手台刻文 → 转盘 3-1-2（保留操作声）。
- **70–82s 开门**：石门开启，镜头推进密室；石台手稿。
- **82–90s 收尾**：结局面板 + 字幕"由 Aholo Lux3D 生成的 17 件资产（进行中）驱动"，附技术栈角标。

## 10. 风险与诚实边界

1. **资产质量**：Lux3D 单物体生成受提示词影响；家具类稳定，带文字/复杂符号类需多轮迭代。报告里如实展示迭代对比，而不是只放最好的一张。
2. **LuxReal 接入形态待确认**：公开 API 文档暂只列 Aholo World / Lux3D；比赛期间以官方工作台为准，不承诺"自动调用"。
3. **比赛体量**：16 天做不完 17 件全资产 + 完美视觉；**优先保证"60–90 秒高光体验"完整可玩**。
4. **原创与合规**：Zork 仅作方法论参考，不复用其文案/资产；所有剧情与知识条目原创；引用外部事实均标注来源。
5. **数据口径**：性能/体积/三角面等数据均来自本机实测；比赛报告不得夸大，未验证项标"待验证"。
